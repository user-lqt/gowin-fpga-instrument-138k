## 2. 关键进展：找到了两条真正的根因

### 根因 A：数据与位时钟在同一拍更新

用"慢时钟 + 逐位打印"的探针（`tb_gold_trace.v`，位周期 4 拍，全帧可人眼核对）
把黄金波形打出来后，确认：

```
正确的 din 序列（gl=0xA5, gr=0x3C）：
  kdiv=0..7 : 1 0 1 0 0 1 0 1   = 0xA5 的 b7..b0  ✅
  kdiv=8..15: 0 0 1 1 1 1 0 0   = 0x3C 的 b7..b0  ✅
```

数据序列本身是对的，但接收端解不出，因为 **`din` 和 `bck` 在同一拍变化**，
接收端采到的是变化中的值，导致整体旋转。

**修法**：把数据更新放在 **`bck` 下降沿**，接收端在 **上升沿**采样
（数据在采样沿之前已稳定半个位周期）。

### 根因 B：接收端采样相位与帧边界

用相位扫描实测（`tb_phase.v`）：

```
samp_ph=0 : rx_l=0x52 rx_r=0x1e
samp_ph=1 : rx_l=0x52 rx_r=0x1e
samp_ph=2 : rx_l=0x52 rx_r=0x1e
samp_ph=3 : rx_l=0x25 rx_r=0x3c    <- 右声道完全正确；左声道只差最高位
```

**`samp_ph=3` 时右声道 100% 正确**，说明方案方向是对的。
左声道差最高位的原因是：**帧回绕时没有把接收端的位计数器清零**，
于是左声道从"第 1 位"开始采样，丢了 MSB。

**修法**：帧回绕处（`kdiv == FRAME_BITS-1`）把 `bcnt` 清零。

## 3. 为什么这一轮仍没收敛（工程原因）

我在调试过程中**反复覆盖同一个文件**（`tb_rx_golden.v` 被写成了
`tb_gold_trace.v` 的模块），而 ModelSim 的 work 库在编译失败时
**会继续使用上一次成功编译的旧模块**，导致我看到的输出其实来自旧版本。
这让我误判了好几轮，浪费了大量时间。

**教训**：每次改完必须先确认"编译的是新代码"（例如打印一个版本号），
否则调试的是幽灵。

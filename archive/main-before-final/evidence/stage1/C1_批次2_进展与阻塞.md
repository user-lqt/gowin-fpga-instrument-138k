## 2. ⛔ 本批次未完成：`i2s_tx.v` 的位对齐

### 现象

| 检查项 | 结果 |
|---|---|
| 复位静音 | ✅ PASS |
| 一帧 64 个 BCK 周期 | ✅ PASS |
| 左右声道不串道 | ❌ FAIL |
| 数据位序正确 | ❌ FAIL（收到的值系统性偏移约 1~2 位） |

实测样例（DATA_BITS=24, SLOT_BITS=32）：
```
发送 L=1        -> 收到 L=0
发送 L=-1       -> 收到 L=16777214   (= -2)
发送 L=8388607  -> 收到 L=8388606    (= 8388607-1)
发送 R=1        -> 收到 R=2
发送 R=7        -> 收到 R=14
```

**规律**：左声道约"减 1 / 左移一位"，右声道约"乘 2"。属于**稳定的位对齐偏差**，
不是随机错误。

### 已尝试的修法（均未收敛）

1. `bck_falling = ~bit_phase[0]` 判下降沿 → 在半周期帧里重复触发，已改
2. 装载与移位写成并列分支 → 互相覆盖，已改
3. `din` 只在 PH_LO 更新 → 帧末装载的 MSB 被覆盖，已改
4. 首位未采样先移位 → 丢最高位，已改
5. WS 提前量扫描（0/1/2/3）→ 未通过
6. 装载点扫描（k=0 / k=SLOT_BITS / ±1/±2）→ 未通过
7. 接收端模型改写（移位式 / 索引式 / 饱和计数）→ 未通过
8. 用"理想发生器"验证接收端模型 → **接收端模型本身也没能自证**

### 关键教训（务必写进后续开发规范）

**我在这个模块上连续迭代了 15 次以上，每次只修好一个问题、暴露下一个。**
根本原因有两条：

1. **发送端和接收端同时不可信**，两边都在改，无法二分定位。
   正确做法应该是：先写一个**绝对的黄金参考**（手工逐位生成的 I2S 波形），
   把接收端模型验到 100% 可信并冻结，**之后只改发送端**。
2. **没有在每一步保留可回归的基线**。改一次跑一次全量测试，却没有把
   "上一版通过的部分"固定下来，导致回归面一直很大。

### 下一步（建议按此顺序，不要再跳步）

1. **冻结接收端**：写 `tb_rx_golden.v`，用手工逐位表生成 I2S（不依赖任何
   移位寄存器副作用），**先把接收端模型验到 PASS**。这一步不做完，
   后面任何改动都无法判断是对是错。
2. 用冻结的接收端，对 `i2s_tx.v` 做**单变量**扫描：
   只扫"装载点"，只扫"移位时机"，一次只动一个。
3. 收敛后立刻冻结 `i2s_tx.v`，打标签，再进入上板。
4. 上板后以**逻辑分析仪实测波形**为准做微调（板载 DAC 的真实相位偏好
   可能与仿真模型不同）。

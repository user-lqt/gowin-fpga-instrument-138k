### 三个特别值得肯定的改动

**1. 修掉了两个我没查出来的 PLL 硬约束（最重要）**

你们去读了 UG306，纠正了我推导里的两处错误：

| 约束 | 我的版本 | 你们的版本 |
|---|---|---|
| VCO 范围 | 没查，写了 2950 MHz（620~1300 之外） | **650~1300 MHz** ✅ |
| PFD = FCLKIN/IDIV | **完全没考虑** | **必须 19~81.25 MHz** ✅ |
| IDIV/FBDIV defparam | 漏传（工具按默认 ÷1） | **补齐** ✅ |

**工具报告独立确认了结果**（不是抄注释）：

```
synth_top_syn.rpt.html:
  u_clock_gen/pll_inst/CLKOUT0.default_gen_clk  Generated  81.379 ns  12.288 MHz
synth_top.power.html:
  u_clock_gen/pll_inst/CLKOUT0.default_gen_clk  12.288 MHz
```

**频率精度我独立验算过**（含我之前算错单位的修正）：

```
Fpfd = 50/2       = 25.000 MHz    (19~81.25 内 ✅)
VCO  = 25 × 29    = 725.000 MHz   (650~1300 内 ✅)
CLKOUT0 = 725/59  = 12.288136 MHz
LRCK    = 12288136/256 = 48000.5297 Hz
误差    = +0.53 Hz = +0.0011 % = +0.019 音分
```

**+0.019 音分** —— 人耳可辨阈值约 5~10 音分，这是阈值的 1/300。**音准上等于精确 48 kHz**，
上一版"+0.5 音分、需要换晶振"的结论可以**作废**，不需要 MS5351 或外置晶振了。

**2. `i2s_tx` 的打包移位方案很聪明**

```verilog
sh <= {sample_l, {PAD{1'b0}}, sample_r, {PAD{1'b0}}};   // 64 位一次性加载
```

把左右两个槽打包进一个 64 位移位寄存器，**帧起点加载一次，之后只移位**。
这从根本上消除了我反复踩的"中途装载与移位互相覆盖"问题。
比我试过的所有方案都干净，这是正确的做法。

**3. 补了跨模块集成测试**

`tb_top_integration.v` 用**真实调度器产生的 `bck_en`** 驱动 `i2s_tx`
（而不是合成脉冲），并断言：
- 每帧恰好 128 个 `bck_en`、1 个 `sample_tick`
- 端到端数据能正确解码

这条覆盖以前确实是空白 —— 单独跑 `tb_scheduler` 和 `tb_i2s_tx` 都过，
但"调度器速率 × i2s_tx 每帧消耗"这个耦合关系没人验。**补得对。**

## 二、⛔ 必须修的 bug：`tone_src` 幅度只有满量程的 1/256

### 位置

`rtl/system/tone_src.v:52-53`

```verilog
sample_l <= {{8{rom_data[ROM_DATA_W-1]}}, rom_data};   // ← 只是符号扩展
sample_r <= {{8{rom_data[ROM_DATA_W-1]}}, rom_data};
```

### 问题

`rom_data` 是 **16 位**（范围 ±32767），`sample_l` 是 **24 位**（范围 ±8388607）。
这里只做了**符号扩展到 24 位**，等于把幅度缩小了 **256 倍**。

| 量 | 值 |
|---|---|
| 正弦峰值 | 32767 |
| 24 位满量程 | 8388607 |
| 实际占比 | **0.39 %** |
| 折算到 dB | **约 −48 dBFS** |

而且 `i2s_tx` 把 24 位左对齐放进 32 位槽，DAC 按 24 位满量程还原 →
**输出比正常音量低约 48 dB**。

### 后果

**不是"没有声音"，是"声音非常小"**：DAC 之后的功放要开到极大才能听见，
噪声和失调会被一起放大，听感很差。上板时极易误判成"没出声/接线错了"。

### 修法（二选一）

```verilog
// 方案 A（推荐）：左移 8 位填满 24 位
sample_l <= {rom_data, 8'b0};          // 有符号数左移 8 位 = ×256
sample_r <= {rom_data, 8'b0};

// 方案 B：显式乘增益（便于后续加力度控制）
sample_l <= rom_data * 256;            // 或者用移位表达
```

改完建议加一条断言：**输出峰值应接近 ±8388607 的某个已知比例**（例如 100%）。

## 三、⚠️ 两个隐患（不阻塞上板，但要记入待办）

### 隐患 1：输出是单声道（左右相同）

```verilog
sample_l <= ... rom_data ...;
sample_r <= ... rom_data ...;   // 与 sample_l 完全相同
```

作为"第一声"验证没问题，但**不要忘记后续拆分**。
赛题要求"多声部/多音色/表情调控"，左右声道必须能承载不同内容。
建议在 `tone_src` 里给右声道加一个可配的相位偏移或增益，先把通路撑开。

### 隐患 2：构建告警 `PR1014` 尚未完全定位

```
WARN (PR1014) : Generic routing resource will be used to clock signal
                'i_clk_in_d' by the specified constraint. And then it may
                lead to the excessive delay or skew
```

**已确认不是致命的**：报告里 `u_clock_gen/pll_fb` 走的是 PRIMARY / PBR3，
GCLK_PIN 用量 1/24，说明时钟进了专用时钟网络。

**但仍建议查清**：`i_clk_in_d` 是输入缓冲后的延迟版本，
工具在提示它没走全局时钟资源。若该信号确实只喂给 PLL 输入，可忽略；
若有其他逻辑也用了它，可能引入时钟偏斜。

**动作**：上板后如果出现"PLL 偶发不锁定"或"低频抖动"，
优先回来看这条告警。

## 四、另外两处一致性建议（小）

1. **`tone_src` 的接口注释说"与 A 的 audio_core 一致：sample + valid"**，
   但实际没有 `valid` 端口，`i2s_tx` 也没有对应的 valid 输入。
   阶段 2 接 A 的 `audio_core` 时会出现接口不一致。
   建议**现在就补上 `o_valid`**（或明确写清"本阶段不使用 valid"），
   免得阶段 2 再改接口、又要重跑一遍全部 tb。

2. **`synth_check_top.v` 与 `synth_top.v` 现在参数一致**，前者已无独立价值。
   建议留着当"最小回归工程"并注明用途，否则以后容易误改。

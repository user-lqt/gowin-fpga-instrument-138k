# K230 捏合距离与模拟音量测试

主程序：`E:\GowinProjects\k230_gesture_test\pinch_screen_test.py`

这是独立的单文件程序。复用亚博配套固件中的 AI 库和手部模型，无需复制之前的 `gesture_screen_test.py`。本次只在 K230 配套屏幕上显示，没有连接 FPGA、发送音量命令或生成声音。

## 运行

1. 装好摄像头、配套屏幕和 TF 卡，在 CanMV IDE 连接 K230。
2. 停止当前运行的程序，然后用 **文件 → 打开文件** 打开本次的 `pinch_screen_test.py`。
3. 点击绿色运行按钮。先用 IDE 临时运行，不需要覆盖原有的 `main.py`。
4. 让单只手完整进入镜头，手掌大致正对摄像头；让拇指和食指指尖逐渐靠拢、再分开。

仍需配套的 `hand_det.kmodel` 和 `handkp_det.kmodel`。程序优先从 `/sdcard/kmodel` 查找，也支持 `/sdcard/examples/kmodel` 和 `/sdcard/app/tests/kmodel`。如果之前的手势测试能运行，直接使用原来的模型。需要更改位置时修改本文件顶部 `MODEL_DIR`。

## 屏幕内容

- 实时画面、绿色手掌框和手部骨架。
- 拇指尖（关键点 4）、食指尖（关键点 8）的黄色圆点和连线。
- **指尖距离**：当前图像中两个指尖的二维直线距离，单位 `px`（像素）。不是毫米。
- **相对距离**：指尖距离除以手腕（关键点 0）到中指根部（关键点 9）的距离。
- **模拟音量**：0～100% 及绿色进度条，张开增大、靠拢减小。数值经过死区、平滑与限速，晚于瞬时距离。
- 手移走后距离和音量显示 `--`，清空进度条；不会把上次的数值继续显示为有效测量。

程序不要求先识别出某个固定手势；只要手部关键点有效，就计算捏合距离。若手太小、关键点重合或所需关键点出画面，会提示完整展示手掌。一次只处理面积最大的手，请先用单手测试。

## 首次估计范围

默认采用：

```python
CLOSE_RATIO = 0.15
OPEN_RATIO = 1.60
SMOOTH_TIME_MS = 350.0
VOLUME_DEADBAND = 3.0
MAX_RATE_PER_SECOND = 35.0
```

```text
相对距离 <= 0.15  → 目标音量 0%
相对距离 >= 1.60  → 目标音量 100%
中间范围          → 线性映射
```

这两个端点是估计值。若合拢时仍不接近 0%，观察合拢时的“相对距离”，将 `CLOSE_RATIO` 调整到略高于该读数；若自然张开还达不到 100%，将 `OPEN_RATIO` 调到舒适张开时的读数。始终保持 `0 <= CLOSE_RATIO < OPEN_RATIO`。

针对“太灵敏”的反馈，调节行程从 `0.15～1.20` 扩大为 `0.15～1.60`，同样的距离变化带来的目标音量变化约减少 28%；平滑时间从 120 ms 增至 350 ms；小于 3 个百分点的目标变化忽略；输出每秒最多变化 35 个百分点。从 0% 调至约 100% 需要约 3 秒以上，这是本次有意放慢的调节速度。首次有效入镜直接显示当前姿势，之后才限速；移走手后仍显示 `--`。

如果仍太快，先把 `MAX_RATE_PER_SECOND` 改成 `20.0`；如果感觉太迟钝，先改成 `50.0`，不必同时改全部参数。若最大张开时“相对距离”不足 1.60，再按实测缩小 `OPEN_RATIO`，否则达不到 100%。

用手掌长度归一化，可减轻手前后移动产生的缩放影响。侧转、透视和遮挡仍会影响结果；摄像头测得的是二维投影，不是三维物理距离。平滑时间增大会更稳定，也会增加延迟。需要观察原始映射时，将 `SMOOTH_TIME_MS`、`VOLUME_DEADBAND`、`MAX_RATE_PER_SECOND` 都设为 `0`。

## 先检查这四项

1. 合拢与张开时，像素距离、相对距离都能连续变化，方向正确。
2. 调整估计端点后，合拢接近 0%，舒适张开接近 100%。
3. 保持同一捏合姿势，小幅前后移动手，像素距离变化，但相对距离和模拟音量应更稳定。
4. 移走手应显示 `--`；重新入镜后从当前姿势开始显示。

如果有画面但一直未检测到手，先用张掌检查检测框；如果黑屏，停止后运行同目录的 `camera_lcd_test.py`。模型或初始化报错时，查看 IDE 控制台的 `FAILED at:` 和后面的报错内容。

本机可验证距离计算、缩放/旋转下的相对距离、映射范围、平滑与丢失清除逻辑。摄像头检测质量、模型兼容性、屏幕显示和实际帧率需要在 K230 上验证。

## 怎么操作

初始钢琴、音量 50%，默认暂停。三种音色顺序为钢琴/吉他/编钟，对应 FPGA 编号 0/1/2。保持单只手完整入镜，手掌正对镜头。

| 手势/动作 | 效果 |
|---|---|
| 单独伸食指，保持约 0.4 秒 | 进入音量页，保留当前音量。 |
| 音量页张掌，保持约 0.4 秒 | 开始按手掌高度调音量。 |
| 张掌上移 / 下移 | 位置越高，目标音量越大；位置越低，目标越小。音量缓慢变化，按 0%、5%、10%……100% 显示档位。 |
| 收起手掌、改做其他手势 | 立即停止高度调节，保留当前音量。再张掌保持确认可继续。 |
| 剪刀手保持约 0.4 秒 | 进入音色页，保留音量和音色。 |
| 音色页点赞 / 三指保持约 0.4 秒 | 下一音色 / 上一音色；持续保持只操作一次。 |
| 握拳保持约 0.2 秒 | 暂停。收起手掌的第一帧已停止高度调节，无需等待握拳确认。 |
| 张掌保持约 0.4 秒 | 音色页恢复控制；音量页恢复并开始高度调节。 |
| 手移出画面 | 立即暂停，保留参数；重新入镜后选页或张掌确认恢复。 |

三指是伸出食指、中指、无名指，小指收拢，拇指姿态不限。音量页使用手掌高度控制，点赞和三指仅在音色页切换音色。

手掌可以缓慢移动，不需要挥动或运动速度达到门槛。静止在某个高度时，音量会逐渐到达该高度对应的目标；收起手掌即可保持当时的数值。重新启用会从原音量平滑变化，不会直接跳到新高度对应的数值。

## 屏幕反馈

- 文字直接叠加在完整的摄像头画面上，无不透明底板或分页框。摄像头画面不裁切、不缩小，手掌检测框和关键点继续显示。
- 顶部：当前页、音量/音色、识别到的手势、确认进度。
- 音量页张掌确认后：显示“高度控制中”和“抬手增大，放低减小”。
- 下方文字：当前状态、掌心 Y 坐标和高度对应的目标音量，以及操作提示。上方的音量数值显示平滑后的当前值。

## 调节范围和手感

高度采用手腕和四个指根共五点的平均位置，避免把伸收手指当成手掌升降。默认 640×480 摄像头中，掌心约 **y=192** 对应 100%，约 **y=374** 对应 0%，两者之间线性映射。无需把手移动到画面最顶端或最底端；保持整只手入镜，手太大时可稍微远离镜头。

- 目标死区为 3 个百分点，约对应 5.5 像素的小幅高度变化，减少微抖。
- 音量输出为 0%、5%、10%……100%，每档相差 5 个百分点，保留 0% 静音档。
- 平滑时间常数由 300 ms 加长至 500 ms；内部音量跟随速度由每秒最多 40 个百分点减为 20 个百分点。屏幕输出按 5% 分档，因此显示为逐档变化。
- 档位切换增加 0.75 个百分点的回差，减少临界位置在相邻两档间反复跳动。
- 非张掌帧立即停止调节；重新张掌须保持确认，避免识别恢复时突然调整。
- 画面连续中断超过 0.5 秒时暂停，需要选页或张掌确认恢复。

主程序中的调参项：`HEIGHT_TOP_RATIO`、`HEIGHT_BOTTOM_RATIO` 决定可用高度范围；`HEIGHT_DEADBAND_PERCENT` 决定死区；`HEIGHT_SMOOTH_MS` 决定平滑；`HEIGHT_MAX_RATE` 决定内部音量变化速度；`HEIGHT_VOLUME_STEP = 5` 决定输出档位间隔；`HEIGHT_OUTPUT_HYSTERESIS` 决定边界回差。先用默认值测试。

## 建议测试顺序

1. 单指进入音量页；此时保持原音量。
2. 在画面中部张掌保持约半秒，看到“高度控制中”。
3. 缓慢抬高手，音量应增加；放低手，音量应减小。左右移动时音量基本保持。
4. 在适当音量收起手掌，数值应立即停止变化；重新张掌后缓慢跟随新高度。
5. 剪刀手进入音色页；点赞依次选吉他、编钟，三指依次返回吉他、钢琴；到边界停止。张掌上下移动不改变音量。
6. 回到音量页，确认切页保留参数；握拳、收手或移出画面时停止调节。

## 模型、检查和备份

仍使用同一目录下与亚博固件配套的两个模型：

```text
/sdcard/kmodel/hand_det.kmodel
/sdcard/kmodel/handkp_det.kmodel
```

还会查找 `/sdcard/examples/kmodel`、`/sdcard/app/tests/kmodel`；其他目录可设置 `MODEL_DIR`。不需要新增模型或重新烧写 TF 卡固件。

摄像头、LCD/IDE 显示管线与上一版相同。控制台每约两秒打印 `PERF` 各阶段平均耗时，以及 `STATE` 当前姿势、`height_active`、`palm_y`、`target`、`volume`，便于核对。屏幕 AI FPS 是完整识别及绘制循环的实测吞吐，约每两秒更新；首个统计窗口显示 0，视频层帧率与此不同。

电脑端 33 项检查通过（31 项交互/绘制，2 项预处理缓存），覆盖高度映射、死区、变化速度、平滑、上下限、启用确认、中断恢复、切页和音色控制，另通过语法检查。这些检查不运行 K230 摄像头或模型，识别效果和实际手感待上板确认。

## V4.3 性能检查

此前板上反馈约 10 FPS，即识别循环每次约 100 ms。V4.3 减少了这些重复工作：默认不再绘制一遍文字阴影；不逐帧打印连续音量变化；关键点裁剪区域完全相同时复用原 AI2D 预处理图，区域改变时仍重建，保持映射一致。手掌检测和关键点仍逐帧执行，摄像头及 LCD/IDE 显示配置保留原样。可设置 `TEXT_SHADOW = True` 恢复文字阴影，但会增加绘字开销。

控制台每约两秒出现一条 `PERF AI FPS ... avg ms ...`：

| 字段 | 平均耗时范围 |
|---|---|
| `cam` | 获取摄像头帧 |
| `det` | 手掌检测、检测后处理、选择手掌 |
| `crop` | 配置或重用关键点 AI2D 裁剪预处理图 |
| `kp` | 关键点预处理、推理及后处理 |
| `ctrl` | 交互计算和离散动作日志 |
| `draw` | 文字、检测框、关键点绘制 |
| `show` | 提交 OSD 显示 |
| `gc+wait` | 主动垃圾回收及循环等待等 |

重新运行后，先移走手等约 5 秒，再让单只手完整入镜保持约 5 秒，分别记录 FPS 和完整的 `PERF` 一行。无手时不会执行关键点模型，因此两种情况可能差异明显。当前尚未在板上测得优化后的 FPS，不承诺具体提升幅度。

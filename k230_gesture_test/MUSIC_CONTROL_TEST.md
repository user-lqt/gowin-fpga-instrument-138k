# K230 捏合音量与动态手势切音色测试

主程序：`E:\GowinProjects\k230_gesture_test\gesture_music_control_test.py`

这是独立的单文件测试，显示在亚博 CanMV K230 配套 640×480 屏幕上。**现在只验证交互和屏幕数值，不会改变 FPGA 乐器的声音。** 未初始化 UART，也没有向乐器发送控制命令。

## 运行

1. 在 CanMV IDE 停止之前的程序。
2. 打开 `gesture_music_control_test.py`，点击绿色运行按钮；不用覆盖板端 `main.py`。
3. 等待模型加载，屏幕应显示实时画面、模拟音量 50%、当前音色 1。
4. 先用单手测试，手掌正对摄像头，完整入镜。动态模型会中心裁剪画面，挥手时尽量保持在屏幕中间。

除了原捏合测试使用的两个模型，还需要亚博动态手势例程配套的 `gesture.kmodel`：

```text
/sdcard/kmodel/hand_det.kmodel
/sdcard/kmodel/handkp_det.kmodel
/sdcard/kmodel/gesture.kmodel
```

程序也查找 `/sdcard/examples/kmodel`、`/sdcard/app/tests/kmodel`。三个模型需在同一目录；其他位置可修改文件顶部 `MODEL_DIR`。路径指板端 TF 卡，不能填写电脑的盘符。请使用与亚博固件匹配的模型，不要直接重刷现有 TF 卡。

当前电脑资料里未找到独立的 `gesture.kmodel`；它可能已经在板端 TF 卡中。启动时会检查路径；如果缺失，控制台会显示 `Missing matching Yahboom models`，需从配套模型资源补齐。只有 IDE 安装完成并不足以运行模型。

## 操作

| 动作 | 屏幕行为 |
|---|---|
| 收拢中指、无名指、小指，拇指和食指捏合或张开 | 保持约 200 ms 后开始调节：靠拢减小音量，张开增大音量。 |
| 五指张开，稍停约 0.4 秒 | 显示“请左右挥手（音量锁定）”，进入 2 秒识别窗口。按屏幕提示操作，低帧率下准备时间会稍长。 |
| 识别窗口内向屏幕右侧挥手 | 下一音色。 |
| 识别窗口内向屏幕左侧挥手 | 上一音色。 |
| 一直张掌，或停在挥手终点 | 每轮最多切换一次，不会连续循环切换。 |
| 收拢手指或移出画面，再张掌 | 可开始下一轮识别；收手至少约 300 ms，切换之间有 900 ms 冷却。 |
| 手移开、关键点失效或挥手超时 | 保持已设置的音量和音色，当前距离显示 `--`。 |

默认只有“音色 1/音色 2”两个演示编号，因此左挥和右挥都会切到另一个编号。这是两个选项循环的正常表现。程序没有实现新的音频音色；对接 FPGA 时需与实际音色编号对应。

音色切换采用配套 `gesture.kmodel` 的跨帧输出，并要求手掌有明显横向位移。左右由镜像画面中的位移决定，避免例程类别命名与屏幕方向不一致。若希望按操作者另一套方向定义，修改 `SWAP_LEFT_RIGHT = True`。上下挥手和五指捏合类别在本测试中不绑定动作。

## 音量灵敏度

本版与更新后的 `pinch_screen_test.py` 使用相同参数：

```python
CLOSE_RATIO = 0.15
OPEN_RATIO = 1.60
SMOOTH_TIME_MS = 350.0
VOLUME_DEADBAND = 3.0
MAX_RATE_PER_SECOND = 35.0
```

- 调节范围扩大，同样手指动作带来的目标音量变化约减少 28%。
- 350 ms 平滑，忽略不足 3 个百分点的目标变化。
- 每秒最多变化 35 个百分点；偶发长帧限制单次跳变。
- 挥手时冻结音量；回到捏合调节从保存值缓慢接续，不会直接跳变。
- 如果仍快，先把 `MAX_RATE_PER_SECOND` 改成 `20.0`；如果太慢，先试 `50.0`。
- 端点仍是估计值：若自然张开时相对距离不足 1.60，需按实测降低 `OPEN_RATIO`，才能达到 100%。

两个测试文件各自独立，修改其中一个不会自动修改另一个。

## 首轮验收

1. 三指收拢，缓慢开合拇食指，音量方向正确，保持姿势时不明显来回跳动。
2. 张掌准备和挥手期间，音量保持原值。
3. 张掌静止不切音色；左右挥手每轮只切一次；一直张掌不会反复切换。
4. 手移出画面后音量、音色保持；重新捏合时缓慢接续。
5. 查看控制台 `FPS` 和 `mode/pose`：若识别不到准备动作，先确认 `pose PALM`；若捏合不生效，先确认其余三指收拢后出现 `pose PINCH`。

本机已验证语法、映射与限速、死区、模式互斥、参数保持、切换防连发及绘制边界等纯逻辑。模型加载、检测准确率、LCD 与三模型实际帧率仍需在 K230 上验证。如果报错，请保留 `FAILED at:` 和完整异常；若只有两个手部模型，仍可先运行原捏合测试。

## 代码依据

基于本地亚博 `程序源码/08.Body/09.dynamic_gesture.py` 的 11 输入模型、预处理和左右类别。未直接导入原例程，避免其导入时初始化 UART。去除了方向图片依赖，限制了历史缓存，分离控制与绘制，增加显式准备、退出和冷却。累计分数仅作模型判定门槛，不解释成置信度百分比。

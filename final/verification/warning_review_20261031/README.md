## 尚未消除的时钟风险

PR1014明确指出 `i_clk_in_d` 使用普通布线，可能增加延迟或偏斜。
实际CST固定 `i_clk_in` 到V22，报告标记为EMCCLK。
完整物理报告显示时钟树已使用PRIMARY资源，但不能由此否定局部普通布线路径。
不能把引脚随意改到另一个专用时钟脚，否则会脱离现有板卡连接。
也没有添加虚假的false path或无依据的时钟位置强制约束。

现有Setup/Hold为0，只能说明该次构建在当前约束模型下通过；
不证明物理时钟抖动为0，不替代板上PLL锁定、LRCK频率/稳定性和温压变化验证。
若要消除该风险，需要结合板卡原理图及UG306时钟资源检查可用专用通路，
任何PLL/时钟网络修改均应作为单独候选重新构建、测量，不能暗改提交版。

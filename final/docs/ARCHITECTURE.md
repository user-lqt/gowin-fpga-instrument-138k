# 核心代码与资源复用

以下路径相对 `project/integrated_instrument_64/source/rtl/`。

## 独立声部与共享振荡器

`audio_core/audio_core.v` 管理64个逻辑声部的音高、包络、力度和发声状态。
`audio_core/oscillator_state_bank.v` 按8组×8路组织：每路保存独立的32位相位历史、频率和亮度；组内共享正弦ROM及乘加运算，依次产生各声部样本。

相位按模2^32累加，频率控制字决定步进；高12位寻址4096点正弦表，低位保留调谐分辨率。各次谐波有相应相位历史，但不额外计作独立声部。TEST使用真实声部的基波路径，不用屏幕图形或状态数字代替发声。

重点阅读：

- `oscillator_state_bank.v`：每路状态、ROM寻址和分步算术，已添加结构注释。
- `oscillator.v`、`phase_acc.v`、`wavetable.v`：共享模块与标量参考路径。
- `adsr_state_bank.v`：64路独立包络状态与共享处理。
- `pitch_expression.v`：逐声部滑音及共享颤音计算，同时更新频率控制字和周期，颤音不是音量调制。
- `plucked_string_bank.v`：每弦独立延迟线/噪声，组内共享更新算术，不能合并不同弦的状态。
- `mixer.v`：按声部串行宽位累加、真实左右分配、TEST居中及最终饱和。
- `system/polyphony_test.v`：ALL/GROUP/MUTE方案及控制稳定状态。

报告应区分“64个独立振荡/声部状态”与“64套物理并行运算器”。TEST固定频点为 `(257+32*i)*48000/16384 Hz`，i=0…63；48kHz为设计目标，现场仍须测量。

## 为什么不能继续随意合并

核心按每采样256个音频时钟调度，标称12.288MHz对应48kHz。
当前振荡器每路约13步并含启动调度；8路一组可在增益开始的第134拍之前完成。
若直接把每组增至16路，原调度会超期，不能仅凭“还有空闲运算器”认定可安全合并。
混音起点168拍，64版核心管线延迟为236拍；这不是完整的按键到模拟DAC延迟。

64版已有8组振荡器共享算术、4组增益、4组body、4组滤波、8组弦模型及共享包络，末级串行混音。FFT和显示缓存跨页面复用，不为每页单独实例化FFT。
左右效果器的独立状态是双声道功能所需，不是重复代码就能删除的冗余。

BSRAM326/340约95.9%，是重要限制；CLS约82.8%，Logic约70.3%。不能为了“复用”新增重复FFT/图像缓存，也不能不测时序就改变共享调度。

结论：**已经大量复用，但没有证据证明达到全局最优。** 本次冻结不再改动运算结构。源码中未被所选参数展开的兼容分支不会因此占据对应硬件；删掉文字不等于减少上板资源。

## 迁移清理边界

仅携带工程清单、必要包含文件/ROM表、构建约束、第三方许可证及精简回归；不带历史候选、旧位流、实现缓存、版本库和其他工具链工程。

修正了过时注释和指向缺失生成器的描述；启动脚本改为系统Python，不绑定开发者专用缓存路径。未删除第三方作者/许可证，K230中合法的AI推理术语也保留。
字符串检索只能确认本包未发现指定工具名称等明显字样，不能证明代码创作来源。没有通过改名伪造作者或掩盖第三方来源。

本轮只增加必要注释、文档及便携脚本。原工程未改，冻结FS未变；所有RTL词法和综合指令一致，所有真实ROM/约束/工程配置保持原字节。

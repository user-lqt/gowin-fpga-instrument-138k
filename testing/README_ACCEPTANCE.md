# 高云电子琴测试软件

双击 `start_instrument_acceptance.cmd`，使用本机已有 Python。
详细的逐页操作、各区域作用、文件选择方法见 `docs/操作说明.md`。
没有环境检查或依赖安装工具。

## 本机移动

退出软件后移动整个“测试软件”文件夹，保持内部层级。
中文和空格路径可用，目标目录必须有读写权限。
不要只移动启动脚本，不要在压缩包里直接运行。
软件启动时不连接仪器；本机 Python、Logic 2 需仍可用。

## 保存分类

所有默认位置以当前软件目录为基准，不依赖原工程路径：

| 类型 | 相对路径 |
| --- | --- |
| 原始记录和采集参数 | `measurements/raw/测量类型/记录编号/` |
| 示波器原始屏幕 | `measurements/screens/测量类型/记录编号/` |
| HTML 报告、计算 JSON/CSV、绘图 | `measurements/reports/测量类型/记录编号/` |
| 评分证据汇总 | `measurements/reports/evidence/evidence_编号/` |
| 界面设置 | `config/settings.json` |
| 可选固件存放目录 | `firmware/` |

测量类型：`polyphony` 复音、`latency` 按键延迟、`lrck` 输出采样率、`logic` 逻辑采集。
三个分类目录使用相同的记录编号，对照即可找到同一次测量。
延迟记录编号包含 `firmware_版本[_音色]/K按键/力度/trial_次数`。
钢琴、吉他、编钟分开存放，现有历史记录每键统一编号 `001`、`002`、`003`。
视频延迟另存 `trial_001_video_test`，不计入历史三次。

## 已有资料

直接打开 `measurements/资料总览.html`，按复音、LRCK、钢琴、吉他、编钟查看。
其中包含对应报告、原始数据和示波器原屏入口。
新旧延迟编号映射在 `config/latency_record_numbering.json`；
原始采集 JSON 内的旧试次号保留不变，只用于追溯。
整理记录集中在 `config/history/`，不与测量报告混放。
`installers/` 只存安装包，正常运行不使用该目录中的安装程序。

按键延迟的“已保存”次数仅统计完整采集记录，不代表验收通过。
若下载完成后扫描验证报错，界面显示“数据已保存，联合验证未通过”，
原始数据、示波器原屏均保留；具体原因另存至对应报告目录的
`joint_validation_error.json`。此时不能判定延迟小于 5 ms，
可先用已有记录离线排查，不必仅因该提示重新采集。
数字记录可读时，验证报错还会生成 `scan_diagnostics/diagnostic_编号/report.html`：
包含未滤波数字波形、短跳变计数、较长脉冲周期/宽度与 A/B 低电平重叠统计。
“打开报告”可选择该诊断报告；其中大于 10 µs 的脉冲筛选仅用于排查，
不用于替代原始验证，不生成达标结论，也不自动认定接线错误。

选择报告、原屏、频谱的按钮始终打开对应类型的系统文件选择框；
原始记录选择 `trial.json`（延迟）或 `capture.json`（复音/LRCK），不要选分析 JSON。
已有复音记录原先没有下载原屏，不能补造；新复音下载会保存真实 BMP。
历史原始记录、图像字节保留不变；分类时只修正 HTML 的相对链接。
早期分类核对信息保存在 `config/history/file_layout_migration.json`，不是环境检查工具。

原始 JSON 里的历史路径仅作溯源，不因移动软件而改写。
外部存放的固件不随软件移动；继续采集前重新核对实际烧录文件、仪器和接线。

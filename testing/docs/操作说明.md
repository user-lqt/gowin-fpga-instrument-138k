# 测试软件操作说明

## 通用规则

软件有四个主页面：复音验收、按键延迟、LRCK 采样率、评分证据。
启动、切换页面和打开本地文件均不会自动连接仪器或启动采集。
操作进行中禁止切换测量任务，避免两处同时操作同一仪器。

顶部“检查复音/延迟/LRCK 连接与设置”随当前页面变化，只检查该测量页对应的 IP、通道和采集设置。
它不保存数据，也不证明物理接线正确。顶部只读检查和延迟计划建立不要求 STOP，不会启动或停止采集。
真正下载已有波形或启动自动联合测量前仍须先手动 STOP，避免接管正在运行的采集。
下载时仍会复查连接和设置，不能因为之前检查通过就跳过。
检查弹窗会显示本次测量用途和检查阶段，各页面要求如下：

| 页面/模式 | 专用检查要求 |
| --- | --- |
| 复音验收 | 只检查所选模拟通道；示波器采集率至少 48 kSa/s、原始记录至少 0.342 秒；提示音频量程与稳态记录，不限制触发源和边沿 |
| 延迟：手动示波器测量 | CH1 列、CH2 模拟 L 均开启；建议至少 20 MSa/s、25 ms 记录、触发前 2 ms 和触发后 20 ms；下载前须 STOP |
| 延迟：自动联合测量 | 复用同一延迟波形要求，另查边沿触发、CH1 触发源、下降沿和 0.5～2.5 V 触发电平；正式开始前须 STOP |
| LRCK 采样率 | 只检查所选数字 LCK 通道；提示完整显示 0～3.3 V、至少 10 MSa/s、至少 1 ms 记录及 10～100 µs/div；不套用音频起音、1x 倍率或按键触发要求 |
| 评分证据 | 纯离线，不连接或检查示波器 |

所有页面顶部的只读检查都无需先 STOP。倍率、量程、时基等建议不作为固定档位限制；
真正执行下载时必须 STOP。自动联合测量的触发条件属于必要要求，不满足时不会启动采集。
评分证据是纯离线页，此按钮禁用。字号可选小、标准、大，小窗口可滚动。

所有固件选择都是人工声明，不是 FPGA 读回；选择了文件不等于已核实板上实际固件。
`.fs` 选择框默认位于软件下的 `firmware`，可把需测固件自行放入此处，也可导航到外部固件位置。
软件不会自动烧录或更改 RTL。

## 文件分类与选择

以启动脚本所在目录为基准：

```text
测试软件/
  start_instrument_acceptance.cmd
  instrument_acceptance.pyw
  firmware/
  config/
    settings.json
    latency_record_numbering.json
    retained_source_hashes.json
    history/
  measurements/
    资料总览.html
    raw/
      polyphony/all_64_001/
      latency/firmware_版本[_音色]/K01/medium/trial_001/
      lrck/lrck_001/
      logic/logic_001/
    screens/
      polyphony/all_64_001/screen.bmp
      latency/firmware_版本[_音色]/K01/medium/trial_001/screen.bmp
      lrck/lrck_001/screen.bmp
    reports/
      polyphony/all_64_001/
      latency/firmware_版本[_音色]/K01/medium/trial_001/
      lrck/lrck_001/
      evidence/evidence_001/
```

`raw`：原始二进制和必要采集参数；`screens`：真实仪器原屏；`reports`：分析结果、图像、CSV、HTML。
不要手动混放，也不要只复制一份报告遗漏它引用的图像和原屏。
三处的测量类型和记录编号一致，方便对应同一次数据。
已有资料统一入口为 `measurements/资料总览.html`，按复音、LRCK、钢琴、吉他、编钟排序。
历史延迟各音色、各按键分别编号 `001`、`002`、`003`；视频另列为
`trial_001_video_test`。原始 JSON 内的采集试次号不改写，新旧对应见
`config/latency_record_numbering.json`，因此原采集编号可能大于3。

| 操作 | 系统选择框默认位置 | 选择内容 |
| --- | --- | --- |
| 复音离线分析、ALL/MUTE 对比 | `measurements/raw/polyphony` | 对应记录的 `capture.json` |
| 延迟离线分析、离线扫描验证 | `measurements/raw/latency` | 对应单次的 `trial.json` |
| LRCK 离线分析、汇总 LRCK 来源 | `measurements/raw/lrck` | 对应单次的 `capture.json` |
| 汇总复音来源 | `measurements/raw/polyphony` | ALL 记录的 `capture.json` |
| 离线逻辑 CSV | `measurements/raw/logic` | 同一次按键的 `digital.csv` |
| 选择分析报告 | `measurements/reports/对应测量类型` | `report.html` 或 `comparison.html` |
| 选择示波器原屏 | `measurements/screens/对应测量类型` | `screen.bmp` |
| 选择频谱图 | `measurements/reports/对应测量类型` | 频谱 PNG，不是原屏 BMP |

报告/原屏/频谱按钮每次都允许选择文件，不会悄悄打开另一份“最新”结果。
当前会话有对应文件时，默认定位其所在的分类子目录；取消选择不开始任何分析。
原始记录选择后会检查记录类型、完成状态和必要数据文件，防止把 LRCK 记录当复音等。
完整性与哈希仍由分析引擎进一步核实。

历史复音记录原本没有采集原屏，对应原屏目录可能为空；新下载会保存真实原屏，不用生成图冒充。
清理计划、编号核验等历史维护记录集中在 `config/history/`，不作为当前测量结果。
旧记录中写下的绝对路径是历史溯源信息，不会用于把新数据写回原工程。

## 复音验收

### 各区域

| 区域 | 作用 |
| --- | --- |
| 采集设置 | IP、所选模拟通道、声部数量、板上测试状态、实际固件 |
| 原始记录目录 | 只读显示统一保存位置，“打开目录”进入原始记录文件夹 |
| 两行操作按钮 | 下载、离线重算、ALL/MUTE 对比、选择报告、原屏、频谱，各司其职 |
| 状态与进度 | 下载点数、百分比；分析阶段单独显示，不把分析当成继续采样 |
| 检测结果 | 目标谱峰数、异常数、削顶等工具自检结果及失败原因 |
| 运行日志 | 连接、保存路径、引擎输出和错误细节 |

“声部数量”不是固件版本；“板上测试状态”只是记录声明，软件不会替你切换 TEST 模式。

### 新测量

1. 人工让板上 TEST 进入目标 ALL、GROUP 或 MUTE 状态并稳定。
2. DAC 模拟输出接所选通道，地只接公共 GND；填写 IP、声部数量、状态，选择实际 `.fs`。
3. 自行启动示波器采集，保留至少约 0.342 秒记录，待信号稳定后 STOP。
4. 点击“下载 STOP 数据并分析”，确认设置。该按钮不发 RUN/SINGLE。
5. 等待原屏和原始数据保存、FFT 分析完成，查看检测结果；不通过时先读原因和日志。
6. 点击“选择分析报告…”查看完整频率表、细节图；原屏和频谱分别用对应按钮选择。

### 已有数据和对比

- “选择记录重新分析…”：选单次 `capture.json`，使用原始数据重算，不连接仪器。
- “选择 ALL/MUTE 对比…”：先选 ALL 的 `capture.json`，再选单路静音 MUTE 的 `capture.json`。
  两次必须是相同声部配置、相同固件；只选 GROUP 不能替代 MUTE。
- 对比报告为该 MUTE 记录的 `comparison.html`，普通频谱报告为 `report.html`。
- 工具自检通过不等于已证明 RTL 独立振荡器，也不等于最终比赛验收。

## 按键延迟

按键延迟现为一个页面，不再区分采集页与扫描验证页。

### 页面区域

| 区域 | 作用 |
| --- | --- |
| 条件设置 | IP、次数、音色、音量、音效、力度和实际固件 |
| 按键选择 | 24 键任意选择，不代表选中后已自动切换物理列接线 |
| 计划按钮 | 建立累计补齐/本轮新增计划；“结束本轮”只结束计划，不删数据 |
| 文件按钮 | 选择已有原始数据离线重算；选择报告、原屏、频谱；打开当前或全部原始目录 |
| 当前目标与接线 | 显示目标键、记录号和 CH1 对应列球位，CH2 保持 DAC 模拟 L |
| 测量模式 | 自动联合或手动下载，只显示相应模式的操作控件 |
| 联合接线 | 当前目标下方确认 D0/A、D1/B、D2/同列；检测逻辑分析仪和查看接线说明 |
| 误差预算与采样设置 | 默认收起，设置有依据的分析余量、时基误差及数字采样率 |
| 测量进度 | 各键已保存、分析可用、待复核、可用目标及状态；分析失败不占可用目标 |
| 运行日志 | 采集、逻辑检测、离线复核共用，显示等待按键、保存位置和异常 |
| 离线联合复核 | 页尾默认收起，导入同次示波器及逻辑记录；CSV 列名映射另行展开 |

累计补齐：例如目标 3 次且已有同条件 2 条分析可用记录，只补 1 次。
本轮新增：例如新增 3 次且已有 2 条分析可用记录，本轮可用目标为 5 次；中断重启后应按已显示累计目标补齐。
已保存不等于分析可用。报告须与当前原始数据哈希一致；失败记录保留为待复核，不计入可用目标。
手动模式只统计示波器条件性分析，自动联合模式只统计联合验证；两种统计不可互相替代，也不代表验收通过。
默认采用手动示波器测量。计划期间测量模式锁定，结束本轮后可以切换。
力度标签是人工记录，不是软件自动测得的力度。

### 自动联合模式

1. 核对示波器 CH1=列、CH2=DAC 模拟 L；逻辑 D0=A 行、D1=B 行、D2=同一列；共地。
2. 本页顶部选择“自动联合测量”，选按键、次数、条件和实际固件，建立计划。
3. 在当前目标下方“联合接线”勾选确认；数字采样率默认 24 MHz，可展开“误差预算与采样设置”调整。
4. 示波器先 STOP、CH1 下降沿触发。点击“开始联合测量”，此时不要提前按键。
5. 软件启动逻辑采集并发送示波器 SINGLE；居中置顶提示窗显示“现在按一次 K编号”，并响铃、显示约 15 秒等待倒计时。
   不用点击确认，直接按一次目标键并保持。提示窗自动消失后可以松开，不要再次按键。
6. 等待下载和分析结束。下一次再次点击开始，无需同一条记录按两次。

联合模式现在直接用数字 B 行与列定位 B 扫描窗口，独立分析模拟起音，不再要求五个单触点脉冲。
两份记录仍必须是同一次单键按压，并保留首次列导通前静止段；缺行、错位或异常脉冲仍可能被拒绝。
手动示波器模式没有数字行信号，不会因本次更新取消原推断条件。
新版方法、已有记录复核结果及 K22 首次验证接线见 [联合分析更新说明](DIGITAL_ROWS_LATENCY_UPDATE.md)。

### 手动示波器模式

1. 建立计划后自行启动一次示波器采集，再按目标键；保留按下前静音、A/B 过程与完整起音。
2. 示波器触发并停止后，确认 STOP，勾选“本次已重新采集并停止”。
3. 点击“保存本次”。下载只读 STOP 记录，不代替前面的采集动作。

示波器条件性推断至少需要 5 个完整单触点脉冲及其后稳定的双触点扫描，
并保留按下前静音和起音后的确认区间。分析失败时查看具体原因，不要把同一段 STOP 波形重复保存充数。
扫描证据只排除有原始末端低电平依据的截断末脉冲，不删除中途异常，不降低最少脉冲数量。
重复分析会保存为新的编号报告，不覆盖旧的延迟证据报告。

### 换键接线

按列安排顺序，例如 K1 → K7 → K13 → K19。只用示波器时，这四键 CH1 保持同一列，不必改线。
联合测量时列不变但 A/B 行会变化，必须按当前提示改接 D0、D1 并重新确认。

| 按键组 | A 行 FPGA 球位 | B 行 FPGA 球位 |
| --- | --- | --- |
| K1～K6 | E14 | E13 |
| K7～K12 | C15 | C14 |
| K13～K18 | B13 | C13 |
| K19～K24 | A14 | A13 |

六列依次对应 B16、B15、A16、A15、A20、B20。以上为当前约束的 FPGA 球位，不是排针编号；
实际位置须按已核实接线与原理图确认，不能猜测。地只接已确认的公共 GND。

### 联合设置与离线复核

- 联合接线直接位于开始测量按钮旁，无需切页；手动模式隐藏，展开离线复核时仍可见。
- “检测逻辑分析仪”只检测真实设备，不开始采集，不生成报告。
- “误差预算与采样设置”：额外分析余量、示波器时基误差、数字采样率。误差预算必须有依据。
  余量或时基误差留空时仅输出观察结果，不作 5 ms 达标判定。
- 页尾“离线联合复核”：选择同一次动作的延迟 `trial.json` 和逻辑 `digital.csv`，
  必要时展开“CSV 列名映射”，勾选同次记录确认，再点击“验证并生成报告”。没有有效预算时同样仅观察。
- “接线说明”打开详细接线文档，不是测量按钮。

B 扫描窗口不是直接物理闭合瞬间；报告保留扫描余量、方法敏感性和单次结论的限制。

## LRCK 采样率

| 区域 | 作用 |
| --- | --- |
| 接线提示 | 提醒选择 DAC 数字 LCK，不是 BCK、模拟 L |
| 测量参数 | IP、实际固件 `.fs`、所选通道 |
| 原始记录目录 | 只读显示 LRCK 统一保存地址，可打开目录 |
| 两项人工确认 | 接线与倍率核实；本次采集已重新进行并 STOP |
| 操作区 | 下载并分析、离线重算、选择报告、选择原屏 |
| 进度与日志 | 点数进度、计算阶段、检查建议、失败原因和结果位置 |

操作：LCK 接所选通道、地接公共 GND，设正确探头倍率；自行采集持续时钟并 STOP，
填写 IP、选择真实 `.fs`、勾选两项确认，再“下载 STOP 数据并分析”。
查看 `report.html` 的实测 LRCK、完整周期数、周期 CSV 和原屏。
“选择记录重新分析…”只重算已有 `capture.json` 所属原始数据，不接仪器。

计数使用同方向上升沿的完整周期，不把左右声道跳变算成两个采样周期。
结果是 DAC LRCK 输出采样率，不是示波器采集采样率；观测周期变化不证明无抖动。

## 评分证据

| 区域 | 作用 |
| --- | --- |
| LRCK 原始记录 | 选择 LRCK 的 `capture.json`，与复音来源分开定位 |
| 复音 ALL 原始记录 | 选择 ALL 的 `capture.json`；软件拒绝把 GROUP/MUTE 用作汇总来源 |
| 人工声明数量 | 输入已由 RTL/技术文档另行核查的振荡器数量，软件不会从谱峰数自动推导 |
| 报告目录 | 固定在 `measurements/reports/evidence`，按编号新建，避免覆盖 |
| 证据边界表 | 静态列出已能提供的测量证据和仍需 RTL 证明的事项，不是待点击的测量任务 |
| 操作、进度与日志 | 生成汇总、选择旧汇总报告、显示完整性或固件匹配错误 |

操作：先完成相同固件版本的 LRCK 和复音 ALL 测量/分析，
分别选择两份原始记录，填写人工声明数量，点击“生成条件性证据汇总”。
软件验证来源哈希、记录类型和已存在的分析结果；缺少分析时应回相应页面重算。
生成的 `report.html` 列出 LRCK、频谱证据、声明数量和条件性吞吐量。

此页不连接仪器，不核实板上真实固件，不审查 RTL，也不宣布最终验收通过。
独立相位/频率/包络、纯硬件实时合成、无预录播放，仍需代码和构建证据。

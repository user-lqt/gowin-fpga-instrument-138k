## LRCK 接线

依据用户提供的 `IMG_20261030_202103.jpg` 照片：

- 数字端一排有 `BCK`、`DIN`、`LCK`、`FMT` 等丝印。
- 待测 LRCK 位置是 **`DIN` 与 `FMT` 之间的 `LCK`**。
- 不是模拟端的 `L`，也不是 `BCK`、`SCL`。
- 信号探头尖端接 `LCK`，地只接已确认的公共 `GND`。数字端有 `GND` 丝印。
- 两通道地内部相连，不得接行线、左右声道信号或电源正极。
- 断电夹线，避免金属夹同时碰到相邻焊点；不要拔除原有 FPGA→DAC 连线。
- 本说明未更改或重新指定任何 FPGA 球位/排针。

建议使用实际的 10x 探头和短接地线，并把通道倍率设为 10x。
普通 BNC 鳄鱼夹线仍是 1x，不能仅在示波器上选择 10x。

## LRCK 保存步骤

1. 核对当前烧录版本，优先在页面中填写实际 `.fs` 路径。文件存在时会记录 SHA256；这不是从 FPGA 读回的身份。
2. 选择测量通道。仅所选通道用于 LRCK 计算；不要求两通道同时测。
3. 可从 DC、1 V/div、偏移 0 V、100 us/div、上升沿触发约 1.5 V 开始。倍率必须匹配真实探头。
4. 建议原始采样率至少 10 MSa/s，记录至少 1 ms。实际记录长度以 RAW preamble 为准。
5. 人工重新采集、手动停止，确认看到持续方波；核对没有削波。
6. 勾选接线/倍率确认及“本次已重新采集并停止”，点击“检查并保存本次”。
7. 软件只改波形传输参数，不发 RUN/SINGLE，不改触发、时基、量程；有设置建议时可确认继续。
8. 打开报告，约 48 kHz 对应完整周期约 20.83 us。计数使用上升沿→下一上升沿，不把左右两次跳变算两个采样周期。

原始记录目录为 `measurements/raw/lrck/lrck_001`、`lrck_002` 等，不用日期命名，不覆盖旧记录：

- `measurements/screens/lrck/同编号/screen.bmp`：示波器原屏。
- `raw.bin`、`capture.json`：原始 BYTE、换算参数、仪器、用户版本声明和哈希。
- `measurements/reports/lrck/同编号/` 中的 `analysis.json`、`periods.csv`、`lrck_waveform.png`、`report.html`：计算结果。

不足 20 个完整周期、每周期不足 20 个采样点、幅度不足、接近 ADC 上下限、
周期变化超过 10% 等会解释失败原因。数据下载完成但分析失败时，原始数据保留。
这些检查仍不能自动识别一根线是否真的接在 LCK 上。

## 延迟报告

每次建立计划前，请在“实际烧录文件（人工确认）”选择当前板上对应的 `.fs`。
确认框显示路径和 SHA256。计划固定该文件和哈希，采集子进程不再依赖可变的全局版本；
文件改变会拒绝采集。软件不能从 FPGA 读回版本，换过烧录文件必须重新选择。

保存后点击“选择示波器原屏…”从对应原屏目录选择 `screen.bmp`，点击“当前原始目录”
直接进入该条记录，不必逐层找文件。运行日志也会列出截图的绝对路径。
原屏按钮始终允许手动选择已有 `screen.bmp`。

新采集完成后自动分析。已有记录点击“分析已有记录…”并在
`measurements/raw/latency` 中选择对应 `trial.json`，无须连接仪器。

报告位于 `measurements/reports/latency/同记录编号/evidence/report.html`，包含：

- `b_detail.png/.svg`：CH1 原始数据分箱最小/最大包络、脉宽变化和推断 B 边界。
- `audio_detail.png/.svg`：模拟起音原始数据范围与滤波曲线。
- `review.json`：原始哈希、版本记录、扫描周期、拟合残差、参数敏感性、条件性扫描窗口。
- 主测口径：50 kSa/s 零相位 FIR、15 mV、连续 0.1 ms。
- 对照口径：25/50/100 kSa/s，10/15/20 mV，FIR 与分块均值。

当前算法依赖本项目八行、约 200 us/帧、A/B 相邻扫描行的模型。
需要有足够的 A 单触点脉冲和按下前基线；过短 A→B 间隔、记录不完整、
扫描模型变化、无持续起音等可能无法自动判定。失败会保存原因，不能把保存成功视为延迟通过。
如更改 RTL 扫描方式，应先重新核实模型，不要调整限制以勉强出数。

条件性扫描闭合窗口不是严格物理闭合上界，零相位 FIR 也可能影响起音。
单条记录无论是否小于 5 ms，都不能直接证明所有键、所有力度、所有音色及最坏情况达标。

## 评分证据

选择一份 LRCK 记录和一份复音 ALL 记录，填写人工声明的独立振荡器数量。
软件输出 `人工声明数量 × 实测 LRCK 频率`，不是用示波器采集采样率相乘。

汇总位于 `measurements/reports/evidence/evidence_001` 等独立目录，包含 HTML 和 JSON。
JSON 固定标记 RTL 独立性尚未验证、板上同版本尚未验证、比赛验收未判定。
若两个烧录文件哈希均存在且不同，拒绝组合；即使哈希相同，也仍需确认实际烧录版本。

还需技术文档提供：独立相位/频率/包络的代码、实时合成到 I2S 的数据通路、
ROM 内容说明、实际编译文件清单、构建与烧录文件对应关系，以及分组/静音现场证据。

## 验证边界

本轮开发只进行了离线测试、模拟 SCPI 传输和历史数据复算，没有连接示波器、
没有发起新采集、没有修改 RTL。LRCK 新采集流程仍需接线后进行真实仪器验证。

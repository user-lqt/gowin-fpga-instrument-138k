# 复音验收来源

本目录最初三个 Python 文件来自用户提供的 `复音验收.zip`。
现已将报告 HTML、图表和频率偏差 CSV 的展示改为中文；
`acceptance_scope.py` 的绘图调用改用中文报告函数，采集与频谱判定算法不变。
机器读取的 JSON 字段、状态码和 `peaks.csv` 字段保留兼容。

原压缩包 SHA256：
`0E1141063087E435DE41DADB438D598A09DE9E448C36EF7A3BB1217AAACC8B60`

统一入口：项目根目录 `instrument_acceptance.pyw`。
适配层：`tools/instrument_acceptance_gui.py`。

复音仍使用原有采集、频谱分析、回放、全开/静音对比和 HTML 报告。
延迟仍使用现有 STOP-only 两通道采集，保存截图、原始数据与元数据；
界面保存完成仅表示采集完整，不代表延迟已经分析或满足 5 ms。

两页共享一个窗口，但各自记录各自的版本及采集条件，不假设板上
验收固件与延迟固件相同；切换页签时必须人工确认接线、烧录版本和
示波器设置。运行期间禁止切换页签和并行采集。

## 采集前检查

更新：量程、垂直偏移、显示跨度、水平偏移和延迟采样建议现在仅给出
警告，用户可确认继续。1 V/div 等量程不会仅因超出建议范围而被阻止。
硬性错误仅保留连接/仪器身份、STOP、通道开启、Normal、有效数值及
复音现有分析器要求的最低采样率/记录长度。下文数值为建议配置。
下载进度来自采集器实际已写入的点数，不是计时模拟；复音的读取
完成与后续 FFT 分析完成分开显示。

统一窗口提供“检测示波器”。延迟建立计划及每次保存、复音在线采集
均须通过连接与设置检查；复音离线分析和对比不要求连接仪器。
仅查询仪器状态，不写入量程、时基或采集控制。

规则在 `tools/scope_preflight.py`，是本项目的采集策略，不是比赛验收标准。
时基、水平偏移窗口按本机已有记录的 14 格显示估算，并同时检查原始
存储深度与采样率对应的记录时长。采集器仍再次核对 STOP。

- 延迟：Normal、两通道开启、DC/1x；至少 20 MSa/s、25 ms 原始记录；
  2～10 ms/div；可见窗口至少覆盖触发前 2 ms 和触发后 20 ms；
  CH1 为 0.2～1 V/div 且显示范围包含 -0.1～3.4 V；
  CH2 为 20～500 mV/div，起音附近 ±0.1 V 在显示范围内。
- 复音：Normal、所选通道开启、DC/1x；至少 48 kSa/s；
  原始记录至少 16384/48000 秒；显示跨度至少同等时长，触发位置可见；
  音频通道量程和起音电平可见范围按上述音频策略检查。
- 不依据水平偏移值是否等于某个固定数字判定；检查偏移与时基组合
  后的可见范围。例：延迟 2 ms/div 配 +10 ms 偏移。
- 设置通过不能证明接线正确、音频无削顶、A/B 过程完整、固件相符
  或结果低于 5 ms。需继续审核保存的真实波形。

新计划清空当前界面日志与进度。“本轮已保存”从零开始；
“同条件累计”仍读取磁盘上的完整记录，累计补齐模式不会删除旧记录。

延迟数据继续存放于原项目 `measurements/full_key_latency`，不迁移、
覆盖现有记录。复音保存目录可在复音页中选择。没有改动 RTL。

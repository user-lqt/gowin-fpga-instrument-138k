## 3. 必须统一的接口规则（B 端协议 v1）

所有控制信号共用同一 clk，rst_n 低有效，C 同步释放复位。input_top 的 CLK_HZ 必须等于实际输入时钟频率，默认只是 50 MHz，不代表板载晶振频率。C 使用 PLL 后的时钟时填 PLL 输出频率。

`system_ready` 由 C 在 A/C 能接收事件后拉高，必须同步于 clk。其为 0 时 B 保持复位、行输出高阻；拉高后连续两个时钟分别发送音量参数 33026（界面显示64）、音色 0。A/C 必须从 system_ready 生效起接收，不能再用 input_ready 屏蔽默认参数。input_ready 只表示键盘初始扫描和编码器初始相位采集已经完成。

|输出|规则|
|---|---|
|event_valid/type/note_id/velocity|每个 valid=1 的时钟都是一个事件，允许连续高多拍；公共协议 01=NOTE_ON，10=NOTE_OFF；按下力度127，释放0|
|param_valid/id/value|独立参数通道，同样逐时钟接收；允许与音符通道同时有效；不允许只在 sample_tick 采样|
|param_id=0|界面音量0..127，默认64，每格1；出口映射到0..65535线性增益，默认33026，最大65535|
|param_id=1|音色，0..INSTRUMENT_COUNT-1，默认0；input_top默认只开放1个编号，B扩展测试显式设置4|
|param_id=2..5|预留滑音、调制、滤波、效果混合；本版不发送，不声称实现|
|EVENT_PARAM_CHANGE=2'b11|保留事件码；本版参数走独立 param 通道，不在音符通道再重复发一次|
|ui_page/ui_param_value|0音量、1音色；值是当前选中项|
|ui_dirty|初始化及显示状态变化后通知刷新；C 必须锁存刷新请求，不能因 I2C 忙而丢掉|
|sensor_value|本版固定0，表示未接传感器，不能解释为有效距离/压力|

同拍按下和旋转时，切换优先，该拍旋转忽略。按住不重复切页；复位期间按住，在复位后稳定消抖结束会视为一次按下。上下方向同时有效则抵消。边界限幅，不回绕，不发送无变化参数。

没有 ready/backpressure；A/C 必须每拍接受，或在 C 侧增加队列/参数寄存器。B、A 的声部状态必须共同复位；单独复位 B 无法保证 A 的旧音符关闭。协议宏仍在 input_defs.vh；明天若 C 的 common/event_defs.vh 编码不同，必须统一并重跑双方仿真，不能只改一边。

## 4. 时序、延迟和键位

默认 50MHz：每行100us、完整扫描400us；5次扫描观察确认，稳定后约2.4ms以内加少量流水延迟（机械抖动时间另计）。映射每拍检查一个键，最多再等16拍。编码器相位过滤50us，完整4个合法净跳变才出一个步进；实际相位需长于过滤和同步延迟。按下消抖20ms，此延迟只影响菜单切换，不是音符触发延迟。

这些是设计时序，不是实测输入到 DAC 延迟；整机≤10ms仍需 C 测量。廉价无二极管矩阵会出现三角组合鬼键，本版如实扫描，不宣称任意和弦无鬼键。

逻辑键序 `bit = row*4+column`，BASE_NOTE=60，以下 C4 采用 MIDI60 命名法：

|行|列0|列1|列2|列3|
|---|---|---|---|---|
|row0|S1 / 60 C4|S2 / 61 C#4|S3 / 62 D4|S4 / 63 D#4|
|row1|S5 / 64 E4|S6 / 65 F4|S7 / 66 F#4|S8 / 67 G4|
|row2|S9 / 68 G#4|S10 / 69 A4|S11 / 70 A#4|S12 / 71 B4|
|row3|S13 / 72 C5|S14 / 73 C#5|S15 / 74 D5|S16 / 75 D#5|

S1..S16 表示逻辑行列，排线引脚不能仅凭“8针”猜顺序。断电用万用表导通档按同一行的4键找公共线，再找列线；先用1键确认 note_id，再测16键。

## 5. OLED 对接（由 C 使用）

oled_content 输出 4行×16列 ASCII，每字符8位，适配128×64上8×16字体。C 负责字模、像素转换、SSD1306初始化、I2C与管脚。

开始一帧前给 frame_start 一个 clk 脉冲，下一拍起依次读取 char_addr=0..63 的 char_data；模块锁存这帧的状态，帧内不撕裂。刷新过程中收到 ui_dirty，C 要记住帧后再刷一次。行0音量、行1音色编号、行2 A提供的活跃声部数、行3状态 R/L/I/E（输入就绪/音频锁定/I2S运行/系统错误）。这里只能说“页面内容可用”，不能说屏幕已经点亮。

## 6. 硬件接线：31005 底板的具体建议分配

依据 Sipeed 官方 Tang_Mega_NEO_Dock-138K_31005_Schematics.pdf，Rev1.3，第19页 J13 扩展排针、第7页 BANK2 管脚映射。官方资料：https://api.dl.sipeed.com/fileList/TANG/Mega_138K_60K/02_Schematic/DOCK/Tang_Mega_NEO_Dock-138K_31005_Schematics.pdf 。J13相关信号与球号已逐项核对，实物连接仍待验证。

使用**靠 PCIe 金手指的一条 2×20 排针 J13（SDRAM0 CONN）**，不是靠 PMOD 的 J14。排针有1/2、39/40端标记，奇数一排、偶数一排；按板上标记定位，不能按照片左右猜。先确认对应球号丝印再插线。下表是 B 推荐占用，C 合并时核查和已有 DAC/其他外设是否冲突；若 C 已占用，连线和约束必须同步调整。

|外设信号|B逻辑端口|J13物理脚号|FPGA球号/对应丝印|方向/说明|
|---|---|---|---|---|
|键盘行0|row_out[0]|1|E14|只驱动低或高阻|
|键盘行1|row_out[1]|2|E13|只驱动低或高阻|
|键盘行2|row_out[2]|3|C15|只驱动低或高阻|
|键盘行3|row_out[3]|4|C14|只驱动低或高阻|
|键盘列0|col_in[0]|5|B13|输入，上拉3.3V|
|键盘列1|col_in[1]|6|C13|输入，上拉3.3V|
|键盘列2|col_in[2]|7|A14|输入，上拉3.3V|
|键盘列3|col_in[3]|8|A13|输入，上拉3.3V|
|EC11 A|enc_a|9|B16|输入，上拉3.3V|
|EC11 B|enc_b|10|B15|输入，上拉3.3V|
|EC11 D或E|enc_sw_n|13|A16|输入，上拉3.3V|
|OLED SCL|C的oled_scl|14|A15|C驱动，开漏|
|OLED SDA|C的oled_sda|15|A20|C驱动，开漏/双向|
|共地|GND|12|GND|接EC11 C、按键另一端、OLED GND|

**J13第11脚为5V，禁止用于上述信号上拉或给这些3.3V输入供电。J13第29/30脚通过配置电阻可接信号或电源，本方案不用它们取3.3V。**

3.3V 从板上明确标注3V3的电源脚取：原理图 J8/J9 PMOD 的第1/2脚为+3V3，第3/4脚为GND。以板上3V3/GND标字为准，不能按其他厂商PMOD的常见脚序猜；上电用万用表确认3.3V后断电接线。使用该电源给面包板正轨供电，J13-12接负轨。

### 裸 EC11

需要3只4.7kΩ：A到3.3V一只、B到3.3V一只、D/E中信号端到3.3V一只。C接GND，D/E另一端接GND。金属固定脚不当作信号脚。A/B/C位置以编码器说明书视角为准；D/E可互换。方向相反时改 REVERSE_DIR=1，或在断电后互换A/B。

4.7kΩ在3.3V下闭合电流约0.7mA，与该EC11说明书最小触点电流相比更合适。资料的额定/测试电压为5V，不代表 FPGA 要用5V；本系统只允许3.3V逻辑。没有电阻时先不接裸EC11下载测试，明天带3只4.7kΩ即可；内部弱上拉不能当作已验证等效替代。

### 矩阵键盘

纯8线无源键盘不需要VCC/GND供电，两组线分别连接表内4行4列。列端各用10kΩ上拉到3.3V（共4只），或由C明确配置并验证内部上拉。行不能同时输出推挽高/低；本代码未扫描行是Z，C需要让三态真正落到IO。

薄膜键盘任意三键可能产生第四个鬼键；明天先测试单键、同一行多键和无矩形的对角组合。最终比赛复音若需任意和弦可靠，应换带隔离二极管的键盘矩阵或改硬件。

### 四针 SSD1306 OLED

按模块实际标字接：VCC→3.3V，GND→共地，SCL→J13-14/A15，SDA→J13-15/A20。四针顺序因模块不同不能盲插。确认模块上的SCL/SDA上拉接3.3V；若无板载上拉，分别加4.7kΩ。C未接入驱动前，接上屏幕也不会显示。

DAC/I2S接线沿用C的已验证方案，不擅自替队友分配。以上只占J13的1..10、13..15和GND，C需把这份表加入整机引脚表。

## 8. 明天顺序

1. A/C核对公共协议、参数接收、INSTRUMENT_COUNT（A当前只实现一种，默认1）、实际CLK_HZ和共同复位。
